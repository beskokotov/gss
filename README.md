# Гарант-Сервис Самара

Региональный сайт на React и Vite: система ГАРАНТ, продукты, услуги, полезные материалы, вопросы и ответы, контакты.

## Просмотр без Node.js

Откройте опубликованный сайт https://beskokotov.github.io/gss/ или скачайте автономный файл по адресу https://beskokotov.github.io/gss/preview.html. В этот файл встроены JavaScript, стили, изображения и шрифты; после скачивания его можно открыть двойным щелчком без Node.js и локального сервера.

В архиве исходников готового HTML нет: он создаётся командой `npm run build:preview` и не отслеживается Git, чтобы сборки не вызывали конфликтов при обновлении репозитория.

## Разработка и запуск исходников

Нужен Node.js 24 или новее.

```sh
npm ci
npm run dev
```

Сервер выведет адрес, обычно http://localhost:5173.

Логотипы, шрифты и иллюстрации включены в репозиторий в `public/assets`. Миниатюры новостей загружаются с сайта ГАРАНТ.РУ, поэтому для них нужен интернет. Команда `npm run assets` при необходимости заново скачает оригинальные логотипы и шрифт из указанных источников.

```sh
npm test
npm run build
npm run preview
```

Обновить автономный файл после изменения исходников: `npm run build:preview`.

### Новости из RSS

В блоке «Полезно знать» показываются десять последних публикаций из официальной RSS-ленты ГАРАНТ.РУ: https://rss.garant.ru/news/. Карточки листаются стрелками, клавиатурой или свайпом: на компьютере видны три карточки прежней ширины, на телефоне — одна. Источник отдаёт XML в Windows-1251 и не разрешает браузерный доступ с другого домена, поэтому GitHub Actions читает RSS во время сборки сайта раз в час, после каждого push в `main` и при ручном запуске workflow. Обновлённые новости входят в опубликованную сборку, но не записываются автоматическим коммитом в репозиторий. Если RSS недоступна, публикуется сохранённый снимок `src/news-feed.json`. Для ручного локального обновления выполните `npm run rss:update`, затем `npm run build:preview`.

### Обновление репозитория и публикация

Перед работой получите последние изменения: `git pull --rebase`. После правок выполните `git add .`, `git commit -m "Обновление сайта"` и `git push`. Workflow **Build and publish site** проверит сайт, соберёт `_site/` и опубликует его через GitHub Pages. В настройках репозитория Pages → Source должно быть выбрано **GitHub Actions**.

`preview.html`, `docs/index.html` и `_site/` не отслеживаются Git. Локальный файл превью остаётся доступен после `npm run build:preview`; готовую сборку для Pages можно получить командой `npm run build:pages`. Автоматическая публикация не создаёт коммитов, поэтому обновление новостей не приводит к расхождению локальной и удалённой веток.

Опубликованная главная страница использует обычную сборку Vite: JavaScript, CSS, шрифты и изображения загружаются отдельно и могут кешироваться браузером. Библиотеки React выделены в отдельный файл, чтобы обновление новостей не заставляло повторно скачивать их. Автономный `preview.html` со встроенными ресурсами остаётся отдельным файлом для скачивания. Команды `build:pages` и `build:hosting` формируют оба варианта; перед копированием очищается только соответствующий сгенерированный публичный каталог.

`dist/` содержит готовую статическую сборку. Ее нужно отдавать через HTTP; для открытия двойным щелчком используйте автономный `preview.html`, а не исходный `index.html`.

## Наполнение

- `src/content.js`: контакты, названия 17 продуктов, услуги, материалы, вопросы и ответы.
- `src/product-descriptions.js`: описания всех 17 продуктов; `ProductDescription.jsx` оформляет их в едином стиле.
- `src/JourneySteps.jsx`: четыре этапа работы с общей градиентной лентой и пояснениями при наведении, фокусе или касании.
- `src/ProductHoverSlider.jsx`: лента из 17 карточек. Наведение на левый или правый край плавно прокручивает её; в центре движение останавливается. Стрелки прокручивают по одной карточке. На телефоне работает свайп, с клавиатуры — стрелки, Home и End. Выбор карточки обновляет блок описания без всплывающего окна. При уменьшении движения автоматическая прокрутка и наклоны отключены.
- `src/news-feed.json`: снимок десяти последних новостей из RSS; `scripts/update-rss.mjs` обновляет его.
- `src/App.jsx`: компоненты страницы и интерактивное поведение.
- `src/styles.css`: стили и адаптивные правила.
- `src/Icon.jsx`: локальные SVG-иконки.
- `public/assets/`: оптимизированные логотипы, Omega UI, desktop- и mobile-версии иллюстраций WebP.
- `public/assets/gss-logo-modern-v1.webp`: облегчённый логотип компании. Исходные PNG и неиспользуемый старый логотип ГАРАНТ сохранены в `backups/production-unused-assets-2026-10-30/`.
- `public/assets/product-icon-01.webp` … `product-icon-17.webp`: значки продуктов с прозрачным фоном, 128 × 128. Исходники, общий лист и запросы обработки imagegen сохранены в `backups/2026-10-29-product-icons-originals/`.

Форма «Отправить заявку» рассчитана на серверную отправку через SMTP на `info@gss.ru`: блокирует повторное нажатие, показывает состояние отправки, подтверждение или ошибку с сохранением заполненных полей. PHP-обработчик и инструкция находятся в `server/README.md`. Для подготовки файлов к переезду на хостинг выполните `npm run build:hosting`. До настройки PHP и SMTP реальная отправка не включена; GitHub Pages и локальный HTML не отправляют письма и не показывают ложное подтверждение. Телефон и электронная почта остаются доступны для прямой связи.

## Проверка

Тесты Vitest проверяют якоря, мобильное меню, клавиатурные вкладки, отправку заявки и сохранение текста при ошибках, закрытие диалога и возврат фокуса, управление анимацией, последовательную загрузку слайдов, мобильные изображения и отказ доступа к буферу обмена. Сборка Vite и автономное превью проверяются отдельными командами. Для интеграционной проверки PHP/SMTP используется `npm run test:server` — требования описаны в `server/README.md`.

CSS содержит правила для настольных экранов, планшетов и телефонов, а также `prefers-reduced-motion`. При оптимизации оформления сравнивались размеры и вычисленные стили элементов в Chrome на ширинах 1440, 1024, 390 и 320 px.

## Слайд-шоу в главном баннере

Пять оптимизированных изображений hero-slide-1.webp … hero-slide-5.webp и мобильные версии 800×600 находятся в public/assets. Исходные PNG перенесены в backups/production-unused-assets-2026-10-27. Логотипы снизу слева удалены через встроенный imagegen; верхние надписи сохранены.

Компонент src/HeroSlideshow.jsx переключает кадры каждые 5000 мс. Первый кадр загружается сразу с высоким приоритетом, следующий — отложенно; переход выполняется только после полной загрузки следующего изображения. На экранах до 700 px используются версии 800×600. Плавный переход длится 2,2 секунды; лёгкое движение выполняется через CSS. Кнопка паузы останавливает движение и таймер. Автосмена приостанавливается в скрытой вкладке и при prefers-reduced-motion.

Неиспользуемые исходные изображения и шрифты сохранены в backups/production-unused-assets-2026-10-27. Полный снимок до оптимизации — backups/2026-10-27-before-audit-fixes.
