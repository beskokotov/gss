# Отправка заявок на info@gss.ru

Обработчик рассчитан на PHP 8.2+ с расширениями OpenSSL, Mbstring и Sessions. Реальная отправка выключена до заполнения SMTP. GitHub Pages не исполняет PHP; на GitHub и при открытии HTML двойным щелчком отправка не работает и форма показывает сообщение об ошибке, не имитируя успех.

## Подготовка

1. В папке `server` выполнить `composer install --no-dev --prefer-dist` (Composer: https://getcomposer.org/).
2. В корне проекта выполнить `npm run build:hosting`.
3. Папка `_hosting/public` содержит сайт и `api/request.php`. Её содержимое загружается в корень нового сайта на хостинге.
4. Папку `_hosting/gss-private` разместить рядом с публичной папкой, но **за пределами доступного из Интернета каталога**. Например: `/home/account/public_html` и `/home/account/gss-private`.
5. Скопировать `config.example.php` в `config.php` в приватной папке. Заполнить SMTP: сервер, порт, `tls` (STARTTLS) или `ssl` (неявный TLS), логин, пароль и разрешённый почтовым сервером адрес отправителя.
6. Сгенерировать `secret`: `php -r "echo bin2hex(random_bytes(32));"`. Вставить результат в конфигурацию. Пароль и secret не помещать в Git и не передавать в JavaScript.
7. Указать точные HTTPS-адреса нового сайта в `allowed_origins`; по умолчанию это `https://gss.ru` и `https://www.gss.ru`.
8. Разрешить PHP запись в приватный каталог `rate-limits`, затем установить `enabled => true`.

По умолчанию обработчик ищет конфигурацию по пути `../gss-private/config.php` относительно корня сайта (`DOCUMENT_ROOT`). При другой структуре задать на хостинге переменную окружения `GSS_FORM_CONFIG` с абсолютным путём к приватному `config.php`. Не переносить конфигурацию с паролем в публичную папку.

## Что проверить на хостинге

- HTTPS включён, PHP исполняется, а не отдаёт исходный текст.
- В `api/request.php` запрос GET возвращает JSON с `token`, устанавливает HttpOnly/SameSite-cookie и не раскрывает настроек SMTP.
- Подать свою тестовую заявку: кнопка блокируется во время отправки, подтверждение появляется только после принятия письма SMTP-сервером. Проверить получение на `info@gss.ru`, включая папку «Спам».
- В письме отправитель — настроенный адрес SMTP, а контакт посетителя используется для ответа. Получатель всегда `info@gss.ru` и не задаётся посетителем.
- При неверном SMTP, ошибке сети или недоступном обработчике форма сохраняет введённые значения и предлагает повторить попытку или связаться напрямую.

## Защита

Проверяются Origin, JSON, серверный токен сессии, размеры и форматы полей. Есть скрытое поле-ловушка, лимит 5 попыток за 15 минут на IP и общий лимит 120 в час. Повтор одной успешно отправленной заявки с тем же идентификатором в сессии не создаёт новое письмо. Хранятся только счётчики, HMAC адреса IP и хеши последних отправленных заявок, без текста формы. Не доверяем присланным клиентом заголовкам X-Forwarded-For; при наличии обратного прокси хостинг должен корректно выставлять REMOTE_ADDR. Обычная антиспам-защита снижает число автоматических отправок, но не заменяет CAPTCHA при целевой атаке.

В коде нет открытого CORS: форма и обработчик размещаются на одном сайте. `VITE_REQUEST_ENDPOINT` позволяет изменить путь при сборке, например для API в другом подкаталоге того же домена. Междоменная отправка с GitHub Pages не включена.

SMTP реализован через PHPMailer: https://github.com/PHPMailer/PHPMailer. TLS-проверка сертификатов включена. Параметр `ca_file` нужен только для отдельного доверенного CA, если его требует провайдер; отключать проверку TLS не нужно.

## Локальная проверка обработчика

После установки Composer-зависимостей команда `npm run test:server` из корня проекта запускает временный PHP-сервер и локальный TLS SMTP-приёмник. Нужны PHP 8.2+ с OpenSSL/Mbstring и утилита OpenSSL в PATH. При нестандартных путях можно задать `GSS_PHP_BIN`, `GSS_PHP_EXTENSION_DIR` и `GSS_OPENSSL_BIN`. Проверка не отправляет внешних писем: она проверяет валидацию, токен, поле-ловушку, фиксированного получателя, защиту от дублей, ошибку SMTP и ограничение частоты.
