# Публикация gss.ru через GitHub Actions

Откройте **Actions → Deploy gss.ru → Run workflow**, выберите `main` и режим:

- `deploy` запускает тесты, собирает сайт и публикует артефакт этого запуска. По желанию передайте компактный JSON предыдущего `release-manifest.json` в `baseline_manifest`, чтобы увидеть разницу в итогах сборки.
- `rollback` восстанавливает файлы предыдущего успешного выпуска из серверной копии. Пересборка для этого режима не нужна. При первом успешном деплое резервной версией становится сайт, который работал до запуска Actions. Если версия уже установлена побайтово, повторный `deploy` оставляет прежнюю точку отката.

Подключение использует `SPACEWEB_SSH_PRIVATE_KEY` только в задании `publish`. Предоставьте ему доступ через репозиторный Secret или окружение `spaceweb-production`. При необходимости настройте в этом окружении обязательное подтверждение ревьюером. В переменной `SPACEWEB_SSH_HOST_KEY` хранится публичный ключ в формате `ssh-ed25519 BASE64`. Отпечаток сверяется с `SHA256:fDATcu43/zhAoS18DoD79nQjgUy1/Qmfq07t5VrDAew` перед SSH. Для штатной работы нужен активный SSH-доступ к `bdvgssru@77.222.40.35:22` и `/usr/bin/php8.4` с cURL.

## Как проходит выпуск

Артефакт содержит `site/` с `index.html` и разрешёнными файлами `assets/`, а также `release-manifest.json` с SHA коммита, размерами и SHA‑256. Runner и сервер проверяют контрольные суммы. Через SSH передаётся только содержимое разрешённых путей из манифеста. `.htaccess`, `api/`, `gss-private/`, настройки SMTP и cron находятся вне области выкладки.

Сервер под блокировкой сохраняет прежние файлы и журнал в `/home/b/bdvgssru/.gss-spaceweb-releases/<run_id>-<run_attempt>/`. Каталог расположен вне `public_html` и должен быть на той же файловой системе. Ресурсы устанавливаются первыми, `index.html` заменяется последним атомарным переименованием. Старые хешированные ресурсы остаются на сервере. Новые ресурсы, успевшие загрузиться до отката, тоже остаются доступными для открытых вкладок.

После переключения скрипт проверяет публичный HTML, JS/CSS и JSON от `/api/news` по HTTPS. При сбое запись о выпуске остаётся прежней, а заменённые файлы восстанавливаются из копии. При обрыве SSH runner пробует восстановить незавершённую операцию. Если связь не восстановилась, следующая операция повторит восстановление под той же блокировкой. Ошибку выпуска смотрите в задании `publish`.

При первой выкладке через Actions отправьте одну тестовую заявку через форму и проверьте получение в корпоративном ящике.
