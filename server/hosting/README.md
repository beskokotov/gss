# Размещение «Гарант-Сервис Самара»

## Что передавать на сервер

- `public/` — готовый сайт; только эта папка должна быть доступна из Интернета.
- `gss-private/` — обработчик SMTP, зависимости и пример конфигурации. Папка располагается рядом с `public/`, за пределами корня сайта.
- `server-config/` — примеры конфигураций веб-сервера, не файлы сайта.
- `manifest.json` — дата сборки, информация о новостях и контрольные суммы публичных файлов.

Сайт не требует базы данных и постоянно работающего Node.js. Для формы нужны PHP 8.2+ с OpenSSL, Mbstring и Sessions, исходящий доступ к SMTP и параметры почтового ящика. **Отправка писем не включена до настройки SMTP.**

## Порядок запуска

1. Сохранить копию действующего сайта и его настроек. Сначала развернуть новую версию на тестовом адресе.
2. Разместить `public/` и `gss-private/` рядом, например `/var/www/gss/public/` и `/var/www/gss/gss-private/`. Загружать весь репозиторий в публичную папку не нужно.
3. Для Nginx адаптировать `server-config/nginx.conf.example`: пути к сайту, сертификату и сокету PHP-FPM. Проверить `nginx -t`, затем перезагрузить конфигурацию. Пример рассчитан на размещение в корне домена.
4. Для Apache 2.4 в `public/.htaccess` уже включены кеширование, сжатие и запрет просмотра каталогов. Нужны разрешения `AllowOverride FileInfo Options Indexes AuthConfig`, `mod_headers`, `mod_deflate` и настроенный PHP. HTTPS включить в настройках виртуального хоста или панели хостинга; за обратным прокси редирект настраивает администратор сервера.
5. Создать `gss-private/config.php` из примера. Указать SMTP, `secret`, точные HTTPS-адреса в `allowed_origins`. Инструкция находится в `gss-private/README.md`. Для тестового поддомена добавить его адрес в `allowed_origins`.
6. Разрешить пользователю PHP запись только в приватную папку `rate-limits`. Не выдавать права 777. Секретный `config.php` и SMTP-пароль хранить только на сервере.
7. После заполнения настроек установить `enabled => true`, проверить заявку и фактическое получение письма на `info@gss.ru`.
8. Проверить главную страницу, оба слайдера, окна, мобильное меню, телефон, карту, HTTPS, ответы 404, сжатие и заголовки кеширования. Затем переключить основной домен. Старые индексируемые адреса gss.ru сопоставить с новыми разделами и настроить отдельные 301-редиректы до переключения.

Если структура каталогов отличается, задайте PHP-FPM переменную `GSS_FORM_CONFIG` с абсолютным путём к приватному `config.php`. При обновлении сайта не перезаписывайте этот файл и каталог `rate-limits`. Не удаляйте старые файлы JS/CSS сразу после выпуска: посетитель с открытой старой вкладкой ещё может обращаться к ним.

## Новости и последующие обновления

RSS включается в сборку. В браузере новости не запрашиваются напрямую. Для свежего пакета на компьютере сборки:

```sh
npm ci
npm test
npm run prepare:hosting
npm run check:hosting
```

`prepare:hosting` получает свежие новости во временный файл и собирает сайт, не меняя отслеживаемый `src/news-feed.json`. Если RSS недоступна, используется сохранённый снимок с предупреждением. Дата последней новости указана в `manifest.json`. Команда `build:hosting` собирает воспроизводимый пакет из сохранённого снимка без сетевого запроса.

Для автоматического обновления раз в час настройте эти действия в CI или на отдельной машине сборки и передавайте результат по SSH. На работающем сайте нужно заменять публичные файлы из готовой сборки, а не запускать Vite. При наличии доступа к серверу можно настроить автоматическую доставку; шаблон подключения SSH не содержит паролей и здесь не активирован.

## Что ещё нужно от сервера

Операционная система, веб-сервер (Nginx/Apache/IIS), корень сайта, версия PHP и его расширения, доступ к DNS/HTTPS, параметры SMTP и способ загрузки файлов. Эти параметры в пакет не зашиты. На GitHub Pages PHP-форма не выполняется.
